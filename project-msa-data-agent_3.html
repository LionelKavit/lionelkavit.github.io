The problem

Data everyone has. Context no one can find.

MSA's Dynamics 365 ERP had evolved faster than its documentation. The result: analysts wasting time on trial-and-error queries, business logic locked in a few people's heads, and a data dictionary nobody trusted.

Cryptic column names

📉
Documentation drift
Manual spreadsheets fell behind schema changes immediately. Nobody had time to keep them current.
⏱️
Invisible overhead
Updating docs competed with billable work every time. It always lost.

What I built

Four components. One living data dictionary.

  • 1
    Automated ETL pipelines in Microsoft Fabric
    Designed Lakehouse-to-Warehouse pipelines that continuously extract SQL metadata from Dynamics 365. Custom stored procedures query INFORMATION_SCHEMA views and upsert into staging tables — preserving business definitions while refreshing technical fields on every run.
  • 2
    Stored procedure management via Fabric Copilot agents
    Automated the continuous maintenance of stored procedures so documentation evolves in sync with the schema. Columns added, renamed, or dropped — the pipeline adapts without manual rework.
  • 3
    Conversational Copilot Studio agent
    A prompt-engineered agent that lets data users query definitions in natural language and knowledge owners validate or update them through conversation — no forms, no spreadsheets. Deployable in Teams, Outlook, or any Microsoft tool with a single click.
  • 4
    Power Automate orchestration layer
    Two flows merge Fabric-sourced technical metadata and agent-submitted business definitions into a unified SharePoint list — a single, always-current source of truth for enterprise data knowledge.

Evaluation

Tested across three dimensions.

~80%
Automation efficiency
Refreshing hundreds of column records went from hours of manual work to a single scheduled run — an order-of-magnitude improvement.
"Lighter"
Usability
Users described the system as feeling "lighter" than a spreadsheet. The chat interface removed the blank-page friction that typically kills documentation habits.
Native
Scalability
Built entirely on Microsoft 365 — new tables or domains added by extending Fabric queries and the SharePoint schema, no architectural changes needed.
Honest limitations
  • Trial-domain restrictions (UW–Madison) prevented full Copilot Studio ↔ Power Automate integration; a manual trigger was used as a workaround for the prototype.
  • Tested on synthesized ERP data — performance at true production scale is yet to be validated.
  • AI-generated definitions were occasionally generic, reinforcing that human review remains essential.
Personal reflection
Behind the build

The technical challenge was orchestration — getting Fabric, Copilot Studio, Power Automate, and SharePoint to hand off to each other reliably, at scale, without breaking. That took careful design and a lot of iteration.

The human challenge was subtler: how do you get busy professionals to contribute to documentation without it feeling like a burden? The answer was to embed the experience inside tools they already use — and make it a conversation, not a form. That design decision shaped adoption more than any technical one.

The best AI tools don't replace human judgment. They make it easier to express, capture, and preserve it.
